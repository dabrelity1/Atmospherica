## 2024-10-24 - Coordinate Mapping Traps in Vector Optimization
**Learning:** The codebase constructs `Vec3(x, z, time)` in weather calculations, mapping the Z coordinate to the vector's Y component and Time to Z. When unpacking `Vec3` to primitives for optimization, `pos.y` does not always correspond to vertical position.
**Action:** Always trace `Vec3` constructor arguments `(x, y, z)` to their semantic meaning before replacing with primitives, especially when `Vec3` is used as a generic data container.
## 2024-10-24 - Optimizing ModShaders Rendering Loop
**Learning:** In tick/render-critical paths like `ModShaders.renderShaders()`, redundant intermediate `Vec3` allocations, such as chaining `.multiply(1.0, 0.0, 1.0).add(...)` or generating distances with `.distanceTo()`, create significant GC overhead. Also, expensive transcendental math functions like `Math.pow(x, 3.0)` and `Math.pow(x, 2.5)` can be safely and efficiently unrolled into basic multiplications, and arbitrary roots like `Math.pow(x, 0.5)` can be calculated via `Math.sqrt(x)`.
**Action:** When working in high-frequency Minecraft Forge rendering/tick loops, unpack vectors to primitive distances, construct primitive-based targets directly (`new Vec3(x, fixed_y, z)`), use `.lengthSqr()` instead of `.length()`, and algebraically unroll any fixed-integer/simple fractional exponent `Math.pow` calculations to minimize CPU cycles and object creation overhead per frame.
